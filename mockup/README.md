## Design language (extract from the playbook, binding for all pages)

- **Shell:** dark navy sidebar; Factora logo/wordmark; plant selector; live-data indicator; search field;
  notifications; profile area; responsive dashboard content.
- **Panels:** clean enterprise dashboard — white/light content panels, **blue accent**, green/amber/red
  machine states. *No random gradients. No excessive animation.*
- **Machine states (used consistently everywhere, including the 3D twin):** healthy = green,
  warning = amber, critical = red, maintenance = blue/gray, offline = gray.
- **Honesty rules that show up in the UI:** simulated/demo telemetry is labelled as simulated; every number
  comes from the API (never invented in a component); the agent panel separates *observed data*,
  *prediction*, *evidence* and *recommendation*.
- **Density:** KPI cards at the top, charts mid-page, tables and lists below — that is the mockups' rhythm;
  keep it.

## Deliberate deltas from the current build (decide these before the UI milestone)

1. **Shell theme.** The M1 shell is a dark navy *page*. The mockups specify a dark navy **sidebar** with
   **light content panels** — the shell gets re-skinned at the design-system milestone, not before.
2. **Routes.** `PROJECT_SPEC.md` §2 currently names pages/routes in a different shape (Factory Twin at `/`,
   Machine 360 at `/machines/[machineId]`, Risk Board, Parts, Impact, Work Orders, `/demo`). The playbook's
   ten routes above are what the mockups and prompts assume. These must be reconciled in one place before
   routing is written, or every page will be built against a different map.
3. **Padding for the demo spine.** The playbook's run-of-show is 90 seconds
   (Command Center → Twin → Machine Detail → Agent → part + work order); `PROJECT_SPEC.md` §9 currently
   describes a 5-minute, 6-beat version. Same story, different timing.
4. **Snowflake naming.** The playbook uses database `FACTORA` with schemas `RAW` / `CORE` / `AI` / `DOCS` and
   warehouse `FACTORA_WH` (XSMALL, auto-suspend 60 s); `PROJECT_SPEC.md` §7 currently says
   `FACTORA_{ENV}` with `RAW` / `CURATED` / `ANALYTICS`. Pick one before any DDL exists.
5. **Cost-safety SQL is a human step.** The playbook's warehouse, resource monitor and CoCo credit-limit
   statements are run by the user in Snowsight at setup. `AGENTS.md` rule 7 keeps agents read-only on
   cost-control settings, so no agent will execute them.

## Regenerating these files

```bash
# requires PyMuPDF (pip install PyMuPDF) and the playbook PDF
python3.11 - <<'PY'
import pymupdf as fitz
from pathlib import Path

PDF = "/path/to/factora_build_playbook.pdf"
MOCKUPS = [
    (4, "01-command-center"), (4, "02-factory-digital-twin"), (5, "03-machines-explorer"),
    (6, "04-machine-detail"), (7, "05-predictive-maintenance"), (8, "06-ai-maintenance-agent"),
    (8, "07-work-orders"), (9, "08-spare-parts"), (9, "09-oee-production-analytics"),
    (10, "10-maintenance-planner-reports"),
]

doc = fitz.open(PDF)
pool = {}
for page in doc:
    for info in page.get_images(full=True):
        pool.setdefault(info[0], info)
by_ratio = {round(i[2] / i[3], 4): x for x, i in pool.items()}
placed = {p: [ii["bbox"] for ii in pg.get_image_info()] for p, pg in enumerate(doc, 1)}

out = Path("mockup")
for pno, slug in MOCKUPS:
    box = placed[pno].pop(0)
    ratio = round((box[2] - box[0]) / (box[3] - box[1]), 4)
    img = doc.extract_image(by_ratio[ratio])
    (out / f"{slug}.jpg").write_bytes(img["image"])   # original JPEG bytes, lossless
PY
```

Expected result: ten `.jpg` files, together ≈ 780 KB, with no unused embedded images.
